# 《Era》（时代）· 中国百年人生模拟 (1900–2025)

> 技术展示型开源项目：基于历史真实人口学生命表与重大事件演进的确定性浏览器文字模拟游戏。
> 灵感源自 1in8b.life，采用 Rust WASM 确定性内核、Svelte 5 Runes、WebGPU 宣纸水墨渲染及全流程属性驱动测试。

## 一、项目愿景与产品规格

- **时间跨度**：出生于 1900–1999 年中国某地，终点为 2025 年或死亡。
- **历史地理与人口加权**：依据当年历史人口权重出生。地点库包含“历史名称表”（如北京经历：京师顺天府 $\rightarrow$ 北京 $\rightarrow$ 北平 $\rightarrow$ 北京；深圳 1979 年前为宝安县）。
- **三层事件系统**：
  1. **命运层**：夭折、饥荒、战乱、疫病、意外（由“生命表 × 地区 × 时代修正”判定）。
  2. **时代层**：按年份与历史行政区触发，因地制宜。
  3. **人生层**：升学、择业、婚恋、生育、迁徙、投资、赡养（2–4 个选项，含 3–10 年延迟决算队列）。
- **系统设定**：
  - 四大属性：健康、学识、心情、见识。
  - 关系：自动生成家族树谱（存亡与亲密度）、自然衰减的朋友圈。
  - 经济：底层使用统一“购买力单位（PPP）”，UI 随时代动态换皮为银元、法币、金圆券、第一至五套人民币与配给粮票。
  - 零“纯收益”选项：一切选择皆为资源互挤压与利弊权衡。
- **早夭接续机制（The Other 4）**：未成年夭折时，可无缝移魂切换至“同年同县出生的另外四人”之一继续人生。
- **结局看板**：人生时间轴、家谱全貌、资产与亲情曲线图、同龄 4 人命运对比、可复现种子卡片。
- **适龄规范**：全站标注 **15+**，战争与灾难坚持客观克制呈现，杜绝猎奇与戏谑。

## 二、系统架构约定

```text
era/
├── apps/
│   └── web/            # Svelte 5 (Runes) + SvelteKit 静态预渲染 (PWA)
├── crates/
│   └── era-core/       # Rust WASM 确定性内核 (Xoshiro256++ / 生命表判定)
├── packages/
│   ├── core-wasm/      # wasm-pack 编译输出与 TypeScript 绑定
│   └── data/           # YAML 历史数据与 Valibot 编译期验证管道
├── data/
│   └── SOURCES.md      # 历史事件与人口学数据出处与置信度档案
└── biome.json          # 统一代码风格与类型安全规则
```

### 1. 内核线程隔离
所有随机数抽样、生命表计算、亲友衰减与分支决算必须在 **Web Worker** 内的 Rust WASM 中执行。主线程仅负责 Svelte 5 响应式视图渲染、WebGPU 画布与无障碍交互，杜绝计算密集型任务导致的掉帧。

### 2. 确定性重现法则
模拟状态由 `(seed: u64, tick: u32, action_sequence: Vec<u8>)` 严格唯一定义。完全相同的种子配以完全相同的分支决策，在任何设备与浏览器上均输出二进制一致的人生轨迹。

## 三、代码规范与工程约定

1. **提交信息规范**：严格遵循 [Conventional Commits](https://www.conventionalcommits.org/)：
   - `feat(...)`: 新功能或里程碑核心推进
   - `fix(...)`: 修复漏洞或偏差点
   - `test(...)`: 补充测试（属性测试、蒙特卡洛断言）
   - `docs(...)`: 文档与史料来源更新
   - `chore(...)`: 工具链与依赖升级
2. **代码风格与检查**：
   - 使用 **Biome 2.6.2** 进行格式化与静态检查（单引号、分号、2 空格缩进、最大行宽 100 字符）。
   - TypeScript 启用最强严格模式（`strict: true`, `noUncheckedIndexedAccess: true`）。
3. **史料可追溯性**：
   - 所有事件与地点数据源均须包含 `source` 与 `confidence` 字段，并在 `data/SOURCES.md` 中备案。禁止无依据凭空捏造。

## 四、常用命令速查

```bash
# 安装依赖
pnpm install

# 启动开发服务器 (SvelteKit + HMR)
pnpm dev

# 构建完整制品 (Rust WASM + 数据编译 + 前端打包)
pnpm build

# 运行 TypeScript 与 Svelte 类型检查
pnpm check

# 运行代码规范检查 (Biome)
pnpm lint

# 自动修复格式化与规范 (Biome)
pnpm lint:fix

# 运行前端与数据管道单元测试 + fast-check 属性测试
pnpm test

# 运行 Rust 核心单元测试
pnpm test:core

# 运行蒙特卡洛人口学历史对齐模拟 (M1)
pnpm test:monte-carlo
```

## 六、M0 交付演示与技术取舍说明

### 1. 交付成果演示
- 执行 `pnpm build`：一键触发 `crates/era-core` 编译为紧凑 WASM 二进制（18.45 KB，gzip 仅 8.62 KB）；触发 `packages/data` 针对 `raw/*.yaml` 执行 Valibot 强校验，输出类型安全的预编译数据包；完成 `@era/web` 静态站点预渲染。
- 执行 `pnpm test`：通过 Vitest 与 `fast-check`，在 100 次随机构建的人生年代中自动检测历史地名区间连续性。
- 执行 `pnpm check` 与 `pnpm lint`：全部 0 错误、0 警告。

### 2. M0 关键技术取舍与调整说明
1. **TypeScript 5.9.3 确定为主版本**：通过实时依赖核实，npm 上的 TypeScript 7.0.x 目前属于极早期实验占位包（缺少 `ts.sys` 编译环境），因此确立采用经过全面生产验证的最新稳定编译器 `^5.9.3`。
2. **SvelteKit 3.1.0 架构升级**：SvelteKit 3 取消了旧式的单独 `svelte.config.js`，全部配置直接合并至 `vite.config.ts` 中的 `sveltekit({ adapter: adapter(...) })` 插件中，构建配置更加内聚扁平。
3. **fast-check 捕获边界区间重合**：在 M0 属性测试中，fast-check 迅速捕获了“1912 年清末民初交替时北京地名区间首尾重合”的问题，推动历史地名表精准校订为严格无缝离散区间（清代截至 1911 年，民国北洋自 1912 年起始）。
